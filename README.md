# OWLS Cash

Мобильное приложение для учёта личных расходов. Реализован вариант **2a** дизайн-макета
(`design_handoff_owls_cash`) по стандартам дизайн-системы OWLS.

Три вкладки и экран настроек:

- **Сегодня** — суммы за день и месяц, форма внесения расхода (numpad, «соты» категорий, наименование).
- **История** — все записи по дням; удаление записи удержанием строки с видимой полосой.
- **Дашборд** — итог месяца и доли категорий кольцами, по убыванию суммы.
- **Настройки** (тап по логотипу) — категории: переименовать, сменить иконку, скрыть, добавить, удалить (удержанием), переставить за ручку.

## Стек

Без сборки и зависимостей: HTML + CSS + JavaScript, PWA.

- Устанавливается на iPhone через Safari → «Поделиться» → «На экран „Домой“». Работает офлайн (service worker).
- Данные хранятся локально в `localStorage` (ключ `owls-cash:v1`). Сети и синхронизации нет.
- Шрифты Unbounded и Manrope лежат в проекте (`fonts/`, вариативные woff2, кириллица + латиница).
- Иконки — Lucide, inline-SVG в `js/icons.js` (сгенерировано из `lucide-static`).

## Структура

```
index.html            оболочка: экраны, таб-бар, контейнеры оверлея и листа
css/fonts.css         @font-face для Unbounded и Manrope
css/owls.css          стандарты OWLS: токены, база, общие компоненты, движение
css/app.css           экраны OWLS Cash по макету
js/owls-motion.js     пять приёмов движения: переход экрана, свайп, каскад, удержание, кольцо
js/store.js           хранилище (localStorage) и схема данных
js/icons.js           иконки Lucide
js/app.js             состояние, расчёты, рендер экранов, настройки, лист категории
manifest.webmanifest  PWA-манифест
sw.js                 service worker: кеш оболочки для офлайна
assets/               знак совы, логотип, иконки приложения
```

`css/owls.css` и `js/owls-motion.js` — переносимая часть стандарта: копируются в новое приложение OWLS без правок.

## Схема данных

```
categories: [{ id, name, icon, order, hidden }]
expenses:   [{ id, ts, amount, catId, name }]   // ts — локальное «YYYY-MM-DDTHH:MM:SS», amount — целые рубли
```

Производные значения (сумма за сегодня, за месяц, средний расход на прошедшие дни месяца,
группы истории, доли категорий) считаются из данных и не хранятся.

## Запуск локально

```bash
python3 -m http.server 8765
```

Открыть <http://localhost:8765/>. Service worker регистрируется только на `https:` и `localhost`;
при правке файлов во время разработки сбросьте кеш (DevTools → Application → Clear storage)
или поднимите `VERSION` в `sw.js`.

## Публикация

Статические файлы — подходит GitHub Pages (ветка `main`, корень репозитория) или любой статический хостинг.
`start_url` и `scope` в манифесте относительные, поэтому приложение работает из подпапки.

## Отступления от макета (по стандартам OWLS)

- **Тёмной темы нет**: стандарт OWLS сознательно её не предусматривает, макет её не рисовал. Кнопка темы из шапки не выпущена.
- **Поле «Наименование» — 16px** вместо 15px: правило «шрифт в полях не меньше 16», иначе iPhone масштабирует страницу.
- **Зоны касания не меньше 44**: кнопки 36–38px из макета сохранили размер, но получили расширенную область нажатия.
- **Отклик на нажатие сильнее стандартного**: сжатие до 0.92 вместо 0.96 и быстрое срабатывание (60 мс), по просьбе заказчика. Возврат остаётся мягким.
- **Кнопка «Внести расход» подтверждает действие**: галочка дорисовывается, запись уходит в список через 300 мс. Повторные нажатия в это время игнорируются.
- **Переход между вкладками** — по стандарту OWLS: новый экран приходит со стороны нажатой вкладки (260 мс), строки выходят каскадом, работает свайп.
- **Удаление** — только удержанием с видимой полосой (записи в истории, категории без записей).
- **Раскладка «сот»** держит не больше трёх кружков в ряду и выкладывает ряды зеркально, чтобы фигура не превращалась в лесенку при любом числе категорий. Восемь категорий дают 3/2/3, как в макете.
- **Пустые состояния** для истории и дашборда добавлены; в настройках при пустой базе есть кнопка «Заполнить примерами» с данными из прототипа.
- Редактирование уже внесённой записи в макете не нарисовано и не реализовано — только удаление.
