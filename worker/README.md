# Посредник для разбора через Сову

Приложение открыто по HTTPS, сервер ИИ работает по обычному HTTP — браузер
такие запросы блокирует. Плюс адрес сервера не должен лежать в открытом
репозитории. Между ними ставится посредник: [owls-sova.js](owls-sova.js),
Cloudflare Worker. Адрес Совы живёт в его переменных, приложение знает только
адрес посредника и вписывает его в настройках.

## Выкладка

1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** →
   **Create** → **Worker**. Имя, например, `owls-sova`.
2. **Edit code** → стереть заготовку, вставить всё из `owls-sova.js` → **Deploy**.
3. **Settings → Variables and Secrets**, добавить две переменные:

   | Имя | Значение |
   |---|---|
   | `SOVA_URL` | адрес сервера ИИ с портом, например `http://<адрес>:11434` |
   | `PATH_TOKEN` | случайная строка: она же путь метода, она же пароль |
   | `ALLOW_ORIGINS` | `https://0574545-hash.github.io` |

   `SOVA_URL` и `PATH_TOKEN` заводить как **Secret**, а не как обычные переменные.
4. **Deploy** ещё раз, чтобы переменные подхватились.
5. Собрать ссылку: `https://owls-sova.<ваш>.workers.dev/<PATH_TOKEN>`.
6. В приложении: **Настройки → Ввод расхода → Умный ввод** включить,
   затем **Разбор через Сову** включить и вставить ссылку целиком,
   вместе с путём, в **Адрес разбора**.

## Почему сокет, а не fetch

Обычный `fetch` из воркера на голый IP Cloudflare не выпускает: возвращает
свою же ошибку `1003`, до сервера запрос не доходит. Обойти это доменным
именем нельзя — пришлось бы завести публичное имя для Совы, а её адрес
светить незачем. Поэтому воркер открывает TCP-соединение через
`cloudflare:sockets` и сам пишет запрос HTTP/1.1. Адрес остаётся в секрете.

Заголовок `Origin` серверу не отправляется намеренно: Ollama отвечает `403`
на любой источник, которого нет в её списке разрешённых.

## Выкладка командой

Если удобнее не через панель, в папке лежит `wrangler.toml`. Из папки `worker`:

```
npx wrangler login          # вход в ваш Cloudflare, подтверждается в браузере
npx wrangler secret put SOVA_URL     # адрес сервера ИИ с портом
npx wrangler secret put PATH_TOKEN   # случайная строка, она же путь метода
npx wrangler deploy
```

`ALLOW_ORIGINS` уже прописан в `wrangler.toml`, адрес ИИ туда не пишется —
он заводится отдельной командой и в репозиторий не попадает.

## Проверка на своей машине

```
printf 'SOVA_URL=http://<адрес>:11434\nPATH_TOKEN=test\nALLOW_ORIGINS=http://localhost:8765\n' > .dev.vars
npx wrangler dev --port 8788 --local
```

Файл `.dev.vars` под игнором. В настройках приложения указать
`http://127.0.0.1:8788/test`. Если забыть про `localhost` в `ALLOW_ORIGINS`,
воркер ответит `403`, а приложение молча останется на разборе на устройстве —
так и задумано, но при проверке сбивает с толку.

## Ограничение частоты

Путь-ключ закрывает метод от случайного прохожего, но от того, кто ссылку
увидит, не спасёт. В панели Cloudflare стоит добавить правило:
**Security → WAF → Rate limiting rules**, порядка 20 запросов в минуту
с одного адреса. На бесплатном тарифе доступно одно такое правило.

## Как это работает в приложении

Разбор на устройстве срабатывает мгновенно и всегда. Через полсекунды после
того, как вы перестали печатать, уходит запрос посреднику; пока он идёт,
по низу разбора ползёт тонкая полоска. Ответ приходит — сумма, категория и
наименование уточняются. Не приходит за две секунды, или сервер молчит, или
адрес не вписан — на экране просто остаётся разбор на устройстве, без ошибок
и без ожидания.

Слова, которые вы присвоили категориям сами, Сова не переучивает: ваша правка
главнее любой догадки.

## Чего посредник не делает

- Не обращается ни к чему, кроме `POST /api/chat`.
- Не принимает от приложения ни модель, ни параметры — они зашиты в коде.
- Не пропускает категорию, которой нет в присланном списке.
- Не логирует и никуда не сохраняет то, что вы вводите.
